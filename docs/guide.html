1절대 규칙 5

  1. hex 직접 입력 금지. 색은 토큰 클래스만. 필요한 색이 토큰에 없으면 → 값이 기존 토큰과 같은지 먼저 확인(오타·변종이 많다) → 정말 새 색이면 tokens.json에 추가 후 사용.
  2. 같은 UI 두 번 만들지 않는다. 반복 패턴(2곳 이상, 또는 web·pencil 양쪽)은 DS로 승격하고 소비한다.
  3. 승격 = 카탈로그 데모 동시 등록. 데모 없는 승격은 미완성 (React는 apps/catalog, Vue는 apps/catalog-vue, 패리티면 양쪽).
  4. 시각 무영향 원칙. 리팩토링·토큰화는 before/after 캡처 픽셀 diff 0가 기본. 의도된 시각 변경은 A/B 리포트로 승인받고 커밋.
  5. 페이지(도메인) 단위 커밋. 롤백 가능하게. 커밋 태그는 한글 규칙([FEAT]/[FIX]/[REFACTOR]…).

현재 보유: 버튼류(Button·IconButton·AddDashedButton·TextLink), 칩(Chip·CategoryChip·SelectableChip), 선택(SelectCard·Checkbox), 카드(ActivityCard·PlanCard·PlanFeature·StarGrid·RibbonBadge), 모달(Modal·ModalHeader·ConfirmModal·ResponsiveModal), 인풋(TextInput·Textarea·Selector·SearchInput), 퍼널 셸(SubHeader·NextStepFooter·InHeader), 기타(Spinner·LottieLoadingDots·Badge·Tooltip·Icon 105종) + 로티 자산 5종. 정확한 스펙은 항상 카탈로그가 정본.

4새 컴포넌트 승격 절차

  1. 원본 스펙 그대로 복사 — 디자인 발명 금지. 클래스 문자열을 축자로 옮기고 hex만 토큰화(값 동일 확인).
  2. 위치: React packages/react/src/{buttons|display|inputs|overlays|navigation} / Vue packages/vue/src / 색 packages/tokens / 로티·이미지 packages/assets.
  3. 배럴 export (하위 index.ts + 루트 index.ts) — export 빠지면 소비자가 못 쓴다.
  4. 카탈로그 데모 추가 + 빌드 통과 — 탭 매핑: 버튼→Buttons, 칩→Chips, 인풋→Inputs, 모달·스피너·로티→Feedback & Overlays, 헤더·푸터→Navigation, 카드→Cards.
  5. 가능하면 React·Vue 패리티로 (한쪽만 먼저면 컴포넌트 주석에 사유 기록).
  6. main 푸시 → CI가 pkg/* 브랜치 자동 재생성. 즉시 소비하려면 수동: git subtree split --prefix=packages/X -b pkg/X && git push -f origin pkg/X
  7. 소비 레포에서 로컬 원본 삭제 + import 전환 (승격했는데 로컬 사본 남기면 이중 소스).
외부 런타임 의존(vaul·radix·reka·lottie-web)은 optional peerDependency로만 — DS가 앱 번들을 강제로 키우면 안 된다.

5검증 — 픽셀 diff와 A/B 승인

  1. before 캡처를 수정 시작 전에 (수정 후엔 되돌릴 수 없다). 상태별로: 기본/선택/모달 열림 등.
  2. 수정 후 동일 뷰포트·동일 상태로 after 캡처 → 픽셀 diff. 데스크톱 1440×900 + 모바일 390×844 기본.
  3. diff 0 = 무영향 실증 → 커밋. diff 발생 = 원인 규명(시프트인지 실제 변경인지) → 의도된 변경만 A/B 리포트에 실어 승인 후 커밋.
  4. pencil은 bun scripts/ab-report.ts <config.json>으로 리포트 생성. 캡처는 test-image/에만 저장.

6레포별 함정

레포함정
career-pencil/make/editor의 에디터 크롬(툴바·패널·캔버스 시맨틱 토큰 text-muted/bg-panel 등)은 웹·Tauri 테마 공유 — 브랜드 토큰으로 바꾸면 Tauri 다크가 깨진다. 단 Web_* 프리픽스 컴포넌트는 웹 전용이라 전환 가능. Tauri 공유 확정 5파일(AssetEditFloating·IconEditFloating·ImageCropDialog·ImageActionDialog·EditorCanvas)은 건드리지 않는다.
브레이크포인트: mobile ≤850 / tablet ≤780 (web과 동일 정의). md·sm은 Tailwind 기본.
autolayout 드래그·fills 언두 등 에디터 엔진 규칙은 레포 CLAUDE.md 참조.
frontendtsconfig가 node10 해석 — DS 패키지에 main/types 필수. next.config transpilePackages에 @careernote/react·tokens 유지.
tailwind content에 node_modules/@careernote/react/src/** 글롭 유지 (빠지면 DS 클래스 퍼지됨).
DSVue 컴포넌트는 v4 하이픈 표기로 작성. React 스펙 복붙 시 언더스코어→하이픈 변환 필수.

7에이전트 프롬프트 템플릿

에이전트에게 UI 작업을 시킬 때 아래를 붙여 넣으면 규칙이 컨텍스트에 실린다. 레포 강제층: pencil은 CLAUDE.md, frontend는 AGENTS.md(공유) — Claude Code는 AGENTS.md를 자동으로 읽지 않으므로 frontend에서 Claude를 쓰면 개인 CLAUDE.md 맨 위에 @AGENTS.md 한 줄을 추가할 것 (Codex·Cursor는 네이티브 지원):

이 작업은 CareerNote 디자인시스템 규칙을 따른다:
1. 색은 hex 금지, @careernote/tokens 토큰 클래스만 (frontend=언더스코어, pencil=하이픈 표기)
2. UI는 @careernote/react 또는 @careernote/vue 기존 컴포넌트 우선 — 카탈로그에서 확인:
   https://careernote.github.io/careernote-design-system/ (+/vue/)
3. 반복 패턴을 새로 만들게 되면 멈추고 DS 승격을 제안할 것 (승격 시 카탈로그 데모 필수)
4. 수정 전 before 캡처 → 수정 → after 캡처 → 픽셀 diff 0 확인. 시각 변경은 승인 전 커밋 금지
5. 커밋은 페이지 단위, 한글 태그([FEAT]/[FIX]/[REFACTOR]...)
